# A Cloudflare Worker + D1 app where a left sidebar (search, place list, place detail, review/add forms) sits beside an OpenFreeMap map of reviewed places near Impulse SF.

## Context
We want a small, deployable "places near Impulse SF" review app on Cloudflare. The user opens one page: a sidebar on the left with a search bar and a list of every reviewed place, and a MapLibre map on the right rendering OpenFreeMap vector tiles with a marker per place. Selecting a place (from the list or a marker) shows its reviews and a form to add one. A user can also add a new place by picking its location on the map. Storage is D1; the API is a Hono app on the same Worker that serves the Vite-built React SPA as static assets.

Phase 1 (scaffold) is ALREADY COMPLETE and committed at `base_sha`. Phases 2, 3 and 4 are independent and run IN PARALLEL against fixed contracts in `src/shared/` and `src/client/components/contracts.ts`. Phase 5 wires them together.

## Operational definitions
- **distanceMeters**: great-circle (haversine) distance in meters from `IMPULSE_SF` to the place, Earth radius 6371008.8 m, rounded to the nearest integer.
- **avgRating**: arithmetic mean of `reviews.rating` for the place, rounded to one decimal, `null` when the place has zero reviews.
- **place list order**: ascending `distanceMeters`, ties broken by `name` ascending.
- **matches query** (client search): the query is trimmed, lower-cased, and split on whitespace into tokens; a place matches when EVERY token is a substring of the lower-cased concatenation of its `name`, `address`, `category`, and `description ?? ""`. An empty or whitespace-only query matches every place.
- **user-presentable error**: an `Error` whose `.message` is safe to render verbatim in the UI (for example the `error` field of an `ApiError` response, or "Network error").

## Assumptions
- Impulse SF is at 101 15th St, San Francisco (SoMa / Showplace Square), geocoded to `lng -122.40217, lat 37.76724`. It is a single constant in `src/shared/config.ts` so it can be changed in one place.
- The API is intentionally unauthenticated and world-writable (anyone can add places and reviews); this is a small community tool and auth is out of scope. Every write endpoint validates and bounds its input with zod.
- Search is client-side over the full place list (the list is small); the API has no search parameter.
- Distance is computed by the API and shipped as `Place.distanceMeters` so the client never needs geo math.
- No place editing or deletion in this iteration.
